# 배낭 속 미궁 (Backpack Labyrinth)

1인칭 3D 복도를 내려가며 **배낭 격자에 장비를 배치**하고, **같은 아이템 2개를 합성**해 키우는 자동전투 로그라이크 시제품입니다. 전투는 자동으로 진행되고, 승패는 배낭 배치와 합성에서 갈립니다.

- 플레이: https://sigco3111.github.io/backpack-labyrinth/
- 서버 없는 정적 웹 게임이며 진행은 브라우저(localStorage)에 자동 저장됩니다.
- iPhone·안드로이드 터치와 데스크톱 마우스를 지원합니다.

> 이 게임은 Steam의 *Dungeonbound* (louidev)에서 **규칙의 영감**만 받은 오리지널 구현입니다. 원작의 그림, 코드, 이름, 화면 구성은 사용하지 않았습니다.

## 플레이 방법

1. 거점에서 **내려가기**를 누르면 복도를 따라 내려가며 해골을 만납니다.
2. 전투는 자동입니다. 영웅이 공격할 때마다 **배낭 격자를 위→아래, 왼→오른쪽으로 한 칸씩 훑고**, 지나가는 칸에 있는 아이템이 발동합니다.
   - 무기: 피해 / 방패: 보호막 / 물약: 회복
3. 전리품은 **보관함**에 들어옵니다. 아이템을 **끌어서** 배낭 칸에 놓으세요(모양이 있는 조각이라 빈칸에 맞아야 합니다). 아이템을 누른 뒤 **회전** 버튼(또는 PC에서 R키)으로 돌릴 수 있습니다. 선택한 아이템을 한 번 더 눌러도 회전하고, 끄는 도중에도 회전 버튼이 동작합니다.
4. **같은 아이템 위에 같은 레벨 아이템을 올려놓으면 합성**되어 Lv이 1 오릅니다(최대 Lv13, 아래 '장기 성장 보강' 참고).
5. 잠긴 칸은 금화로 해금합니다. 한 번 누르면 비용 표시, 한 번 더 누르면 해금됩니다.
6. 쓰러지거나 **귀환**하면 거점으로 돌아갑니다. **전리품·레벨·영구 강화는 그대로 유지**되고, 금화로 영구 강화 5종(공격/방어/지속/경제/해금, 각 10단계)을 구매합니다.
7. 정리가 귀찮으면 **자동 정리**(같은 아이템 자동 합성 + 가치순 자동 배치)에 맡길 수 있습니다. 속도 1x/2x/3x, 전투 로그, 효과음 끄기를 지원합니다. 끝이 없는 무한 진행입니다(5층마다 보스).

## 기술

- Three.js (WebGL) + 순수 JS, esbuild로 번들. 3D 모델은 glb를 한 파일(`game.js`)에 내장합니다.
- 게임 규칙(`core.js`)은 렌더링과 분리되어 있어 Node에서 시뮬레이션으로 밸런스를 검증했습니다.
- 저장: localStorage `bp-labyrinth-v1`.

## 모바일 사용성 개선 (2026-10-29)

- **거점 화면을 전체 화면으로**: 거점(영구 강화) 창이 3D 장면 위 약 310px 오버레이에 갇혀 따로 스크롤되던 것을, 거점 모드에서는 3D 장면을 접고 거점 내용이 배낭 위에 일반 문서처럼 펼쳐지도록 바꿨습니다. 강화 목록 전체가 한 화면 흐름으로 스크롤되고, 내려가기 버튼은 화면 아래에 붙어 따라옵니다.
- **강화 버튼 터치 영역 확대**: 거점의 강화 버튼을 카드 전체 너비로 넓혔습니다.
- **탭 회전**: 선택한 아이템을 한 번 더 누르면 제자리에서 회전합니다(기존: 선택 해제). 끌어서 옮기는 도중에도 회전 버튼으로 회전할 수 있습니다.
- **끌기 가장자리 자동 스크롤**: 아이템을 끌 때 화면 위·아래 가장자리에 가까워지면 패널(또는 보관함)이 자동으로 스크롤되어 멀리 있는 칸에도 놓을 수 있습니다.

## 융합 대장간 (2026-10-29)

서로 **다른** 아이템 2개를 합쳐 새 장비 하나를 만듭니다. 같은 아이템 2개를 겹치는 합성(Lv 상승)과는 별개입니다.

- **사용법**: 사이드의 **융합** 버튼 → 재료 아이템 누르기 → 짝이 될 아이템 누르기 (보라색 테두리가 융합 가능한 짝). 그러면 **미리보기**가 열립니다. 결과 장비, 두 재료와의 능력 비교, 모양(칸 수), 놓일 자리를 보여 주며, **「융합하기」를 누르기 전에는 아무것도 사라지지 않습니다.** 「다른 재료 고르기」로 돌아가거나 **융합 중단**으로 끝낼 수 있습니다.
- **결과**: 서로 다른 기본 아이템 11종의 모든 조합(55가지)에 이름과 능력이 있습니다. 예) 검 + 방패 = 수호의 검, 도끼 + 화염 지팡이 = 불타는 도끼.
- **능력**: 더 강한 쪽(무기 > 방어 > 회복)이 주 능력을 그대로 유지하고, 다른 쪽은 추가 효과(보호막/회복은 원래 값의 75%)나 합산(무기끼리·방어끼리는 합계의 95%)으로 들어갑니다. 한 번의 훑기 발동에서 효과가 함께 나옵니다.
- **모양**: 더 큰 쪽의 모양을 따르고, 작은 쪽이 2칸 이상이면 한 칸을 더합니다 (재료 합계보다 칸을 덜 차지).
- **레벨**: 두 재료의 Lv이 같으면 그대로, 다르면 낮은 쪽에 맞춥니다.
- **제한**: 융합 장비끼리는 다시 융합할 수 없습니다. 같은 융합 장비 2개(같은 Lv)는 기존처럼 합성으로 Lv을 올릴 수 있습니다. 결과를 놓을 자리가 없으면 융합 버튼이 비활성화되고 재료는 그대로입니다.
- **재련 (v12 추가)**: 융합 장비는 **같은 종류(무기/방어/회복)·같은 Lv의 기본 장비**를 재료로 재련해 Lv을 1 올릴 수 있습니다 (최대 Lv13). 자리·회전·잠금은 그대로 유지되고 재료 1개만 소모됩니다. 미리보기에서 「재련하기」로 표시됩니다.
- **저장**: 기존 저장은 그대로 이어집니다 (Lv3·합성 6회·열린 칸·보관함을 새 빌드에서 확인).
- 이 규칙은 이 게임의 자체 설계입니다. 원작 *Dungeonbound*의 실제 융합 규칙을 그대로 옮긴 것이 아닙니다.

## 밸런스·성장 곡선 조정 (2026-10-29)

실제 게임 규칙 코드를 Node에 그대로 올려 자동 플레이 시뮬레이션(정책 4종 × 융합 사용 3종 × 2 시드 × 18회 탐험)으로 측정하고 조정했습니다. 저장 형식은 그대로라 **기존 진행은 그대로 이어집니다.**

### 측정으로 확인한 문제

- **성장이 25층에서 뚝 끊김**: 적 공격력이 층당 1.19배로 커지는데 영웅 체력은 Lv당 +10으로 선형이라, 어떤 정책(공격 우선/균형/경제 우선/해금 우선)으로도 18판 후 전부 25층에서 벽에 막혔습니다.
- **골드가 너무 빨리 남음**: 처치 골드가 층당 1.1배로 불어 5~6판이면 강화 25종·잠금 해금 20칸을 전부 사고, 이후엔 50만g 이상 쌓이기만 했습니다.
- **융합은 압도적이지 않음**: 같은 수준에서 아무 쌍이나 다 융합하면 합성 재료가 말라 오히려 최고 층이 25→20으로 하락. 칸이 부족할 때만 쓰는 정책은 25층으로 동일. 칸당 가치로 보면 1칸+1칸 융합(결과도 1칸)이 가장 효율적이고, 큰 장비끼리는 분할이 근소하게 앞서 **정답이 하나로 고정되지 않는 상태**를 확인해 융합 수치는 유지했습니다.

### 바뀐 값 (변경 전 → 변경 후)

| 항목 | 변경 전 | 변경 후 | 의도 |
|---|---|---|---|
| 적 체력 성장 | 층당 ×1.27 | 층당 ×1.24 | 후반 보스전이 무한정 길어지지 않게 |
| 적 공격 성장 | 층당 ×1.19 | 층당 ×1.165 | 한두 방에 쓰러지는 벽을 완만하게 |
| 영웅 체력 | 50 + 10/Lv | 60 + 16/Lv | 선형 체력이 적 성장을 더 오래 따라가게 |
| 처치 골드 성장 | 층당 ×1.1 | 층당 ×1.06 | 골드가 너무 빨리 남는 문제 완화 |

### 조정 후 측정 (같은 시뮬레이션 조건)

| 지표 | 변경 전 | 변경 후 |
|---|---|---|
| 18판 후 도달 최고 층 | 25층 (모든 정책 동일) | 29~30층 |
| 첫 판 결과 | 5층 보스에서 사망 | 8층까지 생존 |
| 강화·해금 전부 사는 시점 | 5~6판째 | 8~9판째 |
| 18판 후 남는 골드 | 약 41만~54만g | 약 31만~44만g |
| 융합 남용 정책 최고 층 | 20~24층 (합성 집중 대비 열세) | 25층 (여전히 열세, 격차 유지) |

25층 부근에서 멈추던 진행이 30층 부근까지 매 판 조금씩(28→29→30) 뚫고 나가는 곡선으로 바뀌었고, 사망·귀환을 반복하는 장르 특성은 그대로입니다.

## 장기 성장 보강 (2026-10-29)

**배경**: 이전 빌드는 강화 25단계와 36칸을 약 10판 안에 전부 사고, 이후 금화가 쌓이기만 했습니다. 장비도 Lv10이 상한이라 시뮬레이션상 최고 층이 30~42층에서 멈췄습니다.

**바뀐 점** (저장 형식은 그대로라 기존 진행·장비·융합·칸 해금은 이어집니다)

| 항목 | 변경 전 | 변경 후 |
|---|---|---|
| 영구 강화 | 5종 x 5단계 | 5종 x **10단계** (6~10단계는 10,000g~500,000g, 능력치는 기존 단계 위에 누적) |
| 해금 계열 후반 | 보관함 확장 1회 | 전리품 장비 레벨 +1(3회), 보관함 확장 2회 추가 |
| 장비 최대 레벨 | Lv10 | **Lv13** (원작 소개의 Lv10에서 늘린 이 게임의 자체 규칙. 기존 Lv10 장비는 그대로) |
| 30층 이후 적 성장 | 체력 x1.24 / 공격 x1.165 (층당) | 체력 x1.215 / 공격 x1.16 (30층까지는 그대로) |
| 28층 이후 전리품 | - | 40% 확률로 층수/6 만큼 높은 레벨 장비 추가 (합성 재료가 후반에도 쌓이게) |

**측정** (자동 플레이 시뮬레이션이며 실제 사람 플레이가 아닙니다): 실제 game.js의 전투 규칙을 Node로 그대로 불러와, 균형/경제 두 지출 정책 x 2 시드 x 85회 탐험, 융합 미사용, 탐험은 최고 층 -2층에서 시작하는 조건으로 돌렸습니다.

| 시점 | 최고 층 (4개 실행 범위) |
|---|---|
| 10판 | 25~30층 (변경 전과 동일) |
| 30판 | 35~45층 |
| 60판 | 45~50층 |
| 80판 | 45~50층 |

- 변경 전 같은 조건은 80판 후에도 30~35층, 강화만 늘렸을 때는 40~43층에서 멈췄습니다.
- 85판 뒤에는 장비가 대부분 Lv13이 되고 50층 전후(5의 배수 보스)에서 다시 벽이 생깁니다. 60층까지 이어진다는 보장은 없습니다. 자동 플레이 정책이 사람과 다르기 때문에 손맛은 실제 플레이로 조정이 필요합니다.

## 융합 재련과 후반 밸런스 재검증 (2026-10-29, v12)

## 인접 보너스 (2026-10-29)

배낭(6x6)에서 **칸이 상하좌우로 맞닿은 장비끼리 효과가 오릅니다.** 이 규칙은 이 게임의 자체 설계입니다. 원작 *Dungeonbound*의 실제 인접 규칙을 확인하지 못해 그대로 옮긴 것이 아닙니다.

- **보너스**: 맞닿은 장비 1개당 효과 **+7%**, 같은 종류(무기끼리·방어끼리·회복끼리)는 **+11%**, 합계 **최대 +30%**까지.
- **적용 범위**: 무기 피해·화상·독, 방패 보호막, 물약 회복, 융합 장비의 추가 효과(보호막/회복)까지 모두 같은 배율이 붙습니다. 망치의 기절 확률은 그대로입니다.
- **배낭만 적용**: 보관함에 있는 장비는 전투에 발동하지 않으므로 보너스도 없습니다. 배낭에 어떻게 붙여 놓느냐가 새로운 배치 전략이 됩니다.
- **표시**: 맞닿은 장비의 칸이 금색으로 빛납니다. 아이템을 선택하면 연결된 이웃 장비가 금색 테두리로 깜빡여 어디와 연결됐는지 보이고, 정보창에 「인접 보너스 +N% (M개 연결: 이름…)」이 표시됩니다.
- **합성·융합·저장과의 일관성**: 보너스는 저장하지 않고 배치에서 즉시 계산하는 파생 값이라 **기존 저장(v1)이 그대로 이어집니다.** 합성으로 Lv이 올라가도, 융합 장비도, 같은 규칙이 그대로 적용됩니다.

**측정** (실제 game.js 규칙 코드를 Node에 올려 확인): 검 Lv3 1개 기준 피해 26.46에서, 검 2개+방패+물약을 붙인 배치(연결 2개, +18%)는 31.22로 정확히 1.18배가 나왔습니다. 같은 종류 2개+다른 종류 2개에 둘러싸인 장비는 36%가 상한 30%로 제한되는 것을 확인했습니다. 융합 장비의 추가 보호막(3.8 x Lv배율)도 같은 배율로 오릅니다. 이 보너스가 50층 부근의 후반 벽을 뚫어준다고 가정하지 않았고, 배치 선택지와 실제 작동을 목표로 했습니다.

## 자동 정리 고도화 + 배치 잠금 (2026-10-29)

「자동 정리」가 인접 보너스를 계산해서 배치합니다. 이 게임의 자체 설계 확장입니다.

- **인접 고려 자동 정리**: 장비를 강한 순으로 놓되, 각 위치·회전마다 인접 보너스가 가장 크게 붙는 자리를 고르고(탐욕 배치), 이후 장비 하나를 옮기는 이동과 두 장비의 위치 교환을 반복하며 개선합니다(휴리스틱 탐색 - 수학적 최적해를 보장하지는 않습니다). 점수는 「장비 위력 x 인접 보너스%」의 합계라서, 강한 장비에 보너스가 붙는 배치를 우선합니다. 마지막으로 기존 방식(왼쪽 위부터 순서대로 채우기)의 결과와 비교해 **더 나쁘면 기존 방식을 택합니다.** 어느 쪽이든 이전 자동 정리보다 인접 합계가 낮아지지 않습니다.
- **전후 효과 표시**: 자동 정리를 누르면 「인접 보너스 합계 A% → B%」, 연결 수, 합성 횟수, 장비별 변화를 결과 창에서 바로 보여 줍니다.
- **배치 잠금**: 아이템을 선택하고 「잠금」을 누르면 금색 테두리와 🔒 배지가 붙습니다. 잠긴 장비는 자동 정리가 움직이지 않고, 자동 합성에서도 빠지며, 실수로 판매되지 않습니다(판매하려면 잠금 해제). 직접 끌어 옮기기, 회전, 수동 합성·융합은 평소대로 가능합니다. 마음에 드는 배치를 만들어 두고 나머지 칸만 자동 정리로 맞추는 식으로 쓸 수 있습니다.
- **저장 호환**: 잠금은 장비에 `lock` 표시 하나만 더하는 방식이라 기존 저장(v1)이 그대로 이어지고, 잠금도 함께 저장됩니다.

**측정** (실제 game.js 규칙 코드를 Node에 올려 확인): 무작위 40개 배낭에서 이전 자동 정리 대비 인접 합계 39개 배낭 증가·1개 동일·0개 감소. 잠긴 장비는 40회 반복 탐색에도 좌표·회전 불변 확인. 무작위 60개 대형 배낭(10~17개 장비)에서 정리 1회 최대 약 0.3초(PC Node 기준).

## 저장 실패 보호 + 상시 자동 융합 (2026-10-30, v35)

- 저장을 읽지 못하는 상황(손상·버전 불일치·일시적 읽기 실패)에서 더는 빈 저장으로 덮어쓰지 않습니다. 자동 저장이 중단되고 복구 안내가 뜹니다
- 복구 안내: 「다시 읽기」 「백업에서 복구」 「새로 시작」. 읽기에 실패한 원문은 별도 백업 키에 최대 2세대까지 보존하고, 복구는 백업이 정상 저장으로 확인될 때만 진행합니다. 「새로 시작」은 진행 대체 경고와 함께 두 번 눌러야 실행됩니다
- 상시 자동 융합(선택 기능, 기본 OFF): 추천 일괄 융합 화면의 「자동 실행」 토글을 켜면, 던전에서 거점으로 돌아올 때마다 추천 조합을 확인 없이 한 번 실행합니다. 잠금 장비는 쓰지 않고, 실행 중 문제가 생기면 실행 전 상태로 되돌립니다. 추정 점수는 칸 절약 중심의 설계 가중치일 뿐 실제 전투 이득을 보장하지 않습니다
- 설정은 별도 키(bp-fzauto)에 저장됩니다. 기존 저장 형식은 그대로이며, 정상 저장은 이전 버전과 같은 경로로 읽고 씁니다

## 배속 5x와 자동 융합 이력 (2026-10-30, v36)

- **전투 배속 5단계**: 「속도」 버튼이 1x→2x→3x→4x→5x→1x로 순환합니다. 배속은 화면 연출만 빨라지는 것이 아니라 **전투 진행 자체가 배수만큼 빨라지는** 방식입니다(프레임마다 전투 시간을 배수로 진행). 공격 판정·확률·드롭 같은 규칙은 전투 시간 기준으로 그대로 적용되므로 결과 규칙은 동일하고, 다만 고배속에서는 프레임당 진행 폭이 커져 세밀한 타이밍 표현이 거칠어질 수 있습니다. 선택한 배속은 다음 실행에도 유지됩니다.
- **자동 융합 이력**: 자동 융합 모달에 「최근 자동 실행」이 최근 5건까지 표시됩니다(실행 건수와 칸 절약 추정치). 자동 실행 이력이 없으면 이 섹션은 나타나지 않습니다.

**검증**: 규칙 코드 Node 검증(배속 5단계 순환·저장값 클램프·5배속 전투 시뮬레이션 안정·이력 표시)과 클라우드 브라우저 격리 실행(버튼 실클릭 순환·배속 저장 유지·자동 실행 후 이력 행 표시)을 확인했습니다. 격리 실행은 배포 코드를 별도 저장소 위에서 구동한 것으로, 실제 저장 데이터에는 접촉하지 않았습니다.


## v37 추천 일괄 융합 멈춤 수정

장비가 많을 때 모든 후보 쌍마다 점유 격자를 다시 만들던 비용을 줄였습니다. 배치 선택 순서와 추천 점수 규칙은 유지합니다. 추천 계산은 짧은 단위로 나누고 계산 중 화면과 취소 버튼을 표시합니다. 계산은 복제 장비에서만 하며 승인 전 장비와 저장을 바꾸지 않습니다. 계산 도중 장비가 달라지면 계획을 버립니다. 귀환 자동 융합에도 같은 분할 계산을 씁니다.

검증: 독립 Chrome에서 v36 합성 데이터 65개 장비는 65.6초 동안 화면을 막았습니다. v37 점유 격자 개선 후 동기 계산은 1.24초였고 실제 UI는 분할 계산 중 계속 반응했습니다. 모바일 크기 화면에서 취소, 한 단계 실행, 전체 실행을 확인했습니다. 기존 배치 탐색과 1,515개 후보 결과가 같았습니다. 수치는 시험 환경 기준이며 실제 휴대폰별 시간은 다릅니다.

## v38 첫 방문 저장 판정 수정

저장 키 조회에 성공하고 반환값이 null인 첫 방문만 새 게임으로 시작합니다. 정상 v1 저장은 이어서 불러오고, 손상된 JSON/불완전한 필수 구조/미지원 버전/저장 공간 읽기 예외는 구별해 보호 화면을 띄웁니다. 이때 원래 저장 키를 덮어쓰지 않고 자동 저장을 막는 규칙과 원문 백업 회전을 유지합니다. 백업 복구에도 같은 필수 구조 검사를 적용합니다. 읽기 자체가 차단되면 배속은 1x로 부팅해 복구 화면에 접근할 수 있게 합니다.

독립 Chrome에서 새 방문과 저장 후 재부팅, 정상 기존 저장, 손상 JSON, 빈 값, 문자열 null, 불완전 v1, 미지원 v2, getItem 예외, 백업 회전과 복구 후 재부팅을 확인했습니다. 기존 공유 프로필이나 실사용 저장으로 시험하지 않았습니다.
